# Limpeza local e reset de cache

## Escopo confirmado

O usuário quer esvaziar dados armazenados, mantendo cache e carregamento
progressivo. Confirmou manter testes isolados e suas fixtures, sem carregá-los
no site. Preservar aprovação manual, simulador e integração real Pix Sicredi.

## Alterações

- `cache-generation.mjs`: nova geração `cf-public-20261023-reset1`; exclusão
  explícita do banco anterior `cf-public-20261023`. Não enumera nem remove bancos
  de outros aplicativos ou credenciais. Não importa dados antigos.
- `tab-session.js` / `storage-cleanup.js`: rotina compartilhada nas telas que
  usam a sessão, com limpeza dos snapshots legados e Cache Storage Conflora.
  Trabalho assíncrono sem bloquear autenticação ou interface. A geração nova
  impede uso de dados anteriores mesmo enquanto outra aba bloqueia a exclusão.
- `public-catalog.mjs`: mecanismo mantido, passando a usar a geração nova.
- `pdv/app.jsx`: removido leitor obsoleto que sempre retornava um Map vazio e
  mesclagem de imagens desse mapa. Imagens atuais continuam vindo do backend.
- `views-admin.js`: centralizada a carga comum de produtos, preços e estoque.
- Removidos cinco arquivos do exemplo Data Connect de mentoria e cinco arquivos
  do SDK gerado correspondente. Sem importadores no runtime, scripts ou pacote;
  não havia configuração desse serviço em firebase.json. Nenhum recurso remoto
  foi excluído. Firestore continua sendo usado normalmente.
- Varredura por hash de fontes rastreadas não encontrou arquivos inteiramente
  duplicados no escopo analisado (exclui testes, traduções, SDKs gerados, vendor
  e lockfiles). Isso não prova ausência de toda duplicação lógica no projeto.

## O que permanece intencionalmente

Fixtures e doubles dos testes, guardas que rejeitam respostas mock de provedores,
traduções, configurações reais, fluxos manuais/automáticos Sicredi e seus testes.
Os testes ficam fora de public/ e são excluídos do pacote Cloud Run por
.gcloudignore. As entradas dos builds não importam test/.

## Aplicação efetiva

Esta é uma mudança no código local, não uma limpeza já comprovada nos aparelhos.
Build local concluído; requer publicação autorizada. Cada navegador aplica o reset ao abrir a
nova versão. Abas antigas não são recarregadas à força durante uma venda; devem
ser fechadas/reabertas quando a operação estiver segura. Exclusão bloqueada é
tentada novamente na próxima visita. Caches em memória do servidor reiniciam
com o novo processo; nenhum endpoint de apagar produção foi criado.

Não se apagam registros do Firestore, tokens, preferências nem operações
pendentes. Assets estáticos HTTP versionados não são dados comerciais e continuam
usando cache normal. Não foram executados testes funcionais nem feito deploy.

## Verificações desta limpeza

Sintaxe de sete arquivos e do script administrativo embutido aprovada. Lint dos
cinco JS alterados nesta etapa aprovado. `npm run build:frontend` concluído após
a restrição de leitura do esbuild exigir execução fora do sandbox. Verificados
35 inputs no manifesto da vitrine: nenhum teste, SDK Data Connect removido ou
QueryClient antigo. Teste de navegador preparado para exclusão da geração anterior
e preservação da geração atual, ainda não executado. Esses checks não substituem
homologação de cache, conexão instável, Pix e vendas.
